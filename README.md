# ПП.09 — корпоративный сайт «Тензор — Ярославль»

Node.js и PostgreSQL. Общедоступные страницы и API работают в одном приложении. База размещается в Neon, приложение — одним Node Web Service в Render.

## Состав

- Четыре страницы ПП.08: главная, проекты, карьера и контакты.
- Каталог: поиск, направление, заказчик, технология, сортировка и сброс.
- Обращения: проверка полей, сохранение, связь с проектом и обработка статуса.
- Администратор: вход `/login`, проекты `/admin`, обращения `/admin/inquiries`, статистика `/admin/stats`, журнал `/admin/audit`.
- Схема `pp09`: 12 таблиц, первичное наполнение 168 записями, включая 24 проекта и 40 учебных обращений.
- Резервное копирование и восстановление в пустую БД.
- 16 автоматизированных проверок SQL, HTTP и клиентского DOM.

## 1. Создать базу Neon

1. В [Neon](https://neon.com) создайте проект и **новую пустую базу `pp09_v3`**. Старую базу предыдущей версии оставьте отдельно.
2. В окне подключения выберите эту базу и роль. Скопируйте PostgreSQL connection string с включенным pooling в `DATABASE_URL`.
3. Отключите pooling и скопируйте прямую строку в `DATABASE_URL_DIRECT`. Прямой hostname не содержит `-pooler`.
4. В обеих строках должен присутствовать параметр `sslmode=require`. Если Neon добавляет `channel_binding=require`, оставьте его.

Файлы БД отдельно на Render не загружаются: скрипт инициализации создает структуру и начальное наполнение в Neon. SQL использует отдельную схему `pp09`; он не удаляет старые таблицы схемы `public`.

## 2. Локальный запуск (Windows PowerShell)

Установите Node.js 22 или 24 LTS. Откройте терминал **в каталоге с `package.json`**.

```powershell
Copy-Item .env.example .env
npm ci
```

В `.env` укажите две строки подключения Neon, свой `ADMIN_USER` и пароль из 12–200 символов. Логин — 3–50 латинских букв, цифр, точек, дефисов или подчеркиваний.

```powershell
npm run local:init
npm test
npm run local:start
```

Откройте `http://localhost:3000`, вход — `http://localhost:3000/login`. Для завершения сервера нажмите Ctrl+C.

Начальное наполнение выполняется только при пустом справочнике категорий. Повторная инициализация не удваивает данные и не возвращает удаленные проекты. Повторный `local:init` обновляет пароль указанной учетной записи из `.env`.

Тесты работают на собственных БД PGlite и не подключаются к рабочему Neon. Клиентские сценарии выполняются в jsdom; проверка внешнего вида выполняется в браузере.

## 3. Публикация в Render

1. Создайте GitHub-репозиторий и загрузите **содержимое этого каталога**. `package.json` должен лежать в корне. `.env`, `node_modules` и резервные копии не загружайте; `.gitignore` уже настроен.
2. В [Render](https://render.com) выберите **New → Web Service**, подключите репозиторий, ветку `main`, язык **Node**. Root Directory оставьте пустым.
3. Build Command: `npm ci --omit=dev`.
4. Start Command: `npm run db:init && npm start`.
5. Health Check Path: `/healthz`.
6. Добавьте переменные окружения:

| Переменная | Значение |
|---|---|
| `NODE_VERSION` | `22` |
| `NODE_ENV` | `production` |
| `DATABASE_URL` | PostgreSQL URL Neon с pooling |
| `DATABASE_URL_DIRECT` | Прямой PostgreSQL URL Neon |
| `ADMIN_USER` | Ваш логин |
| `ADMIN_PASSWORD` | Ваш пароль от 12 символов |

7. Создайте сервис. В логах должны появиться сообщения о готовности схемы и прослушивании порта.
8. Откройте выданный HTTPS-адрес, затем `/healthz`: ожидается `{"status":"ok","schema":"pp09"}`. В `/projects.html` должны отобразиться проекты; в `/login` — форма входа.
9. Выполните локально `npm run smoke -- https://ИМЯ-СЕРВИСА.onrender.com`, затем проверьте вход, форму обращения, добавление и удаление тестовой карточки.

Можно использовать `render.yaml` через New → Blueprint. Ручная настройка выше дает тот же результат. Дополнительный frontend-сервис и отдельный Render PostgreSQL не нужны.

Если сервис размещен на бесплатном плане, первый запрос после простоя может запускать его заново. Дождитесь ответа `/healthz` перед скриншотами.

## 4. pgAdmin 4

1. Загрузите Windows x64 installer с [официальной страницы](https://www.pgadmin.org/download/pgadmin-4-windows/).
2. Снимите окна лицензии, каталога установки и завершения до перехода к следующему шагу.
3. Откройте pgAdmin, **Servers → Register → Server**.
4. General → Name: `PP09 Neon`.
5. Connection: прямой Host Neon, Port `5432`, Maintenance database `pp09_v3`, Username и Password из Neon.
6. В параметрах подключения установите `sslmode=require`: в новых версиях это вкладка Parameters; в старых версиях может быть отдельная вкладка SSL. Сохраните подключение.
7. Откройте **Databases → pp09_v3 → Schemas → pp09 → Tables**. После `local:init` видны 12 таблиц.
8. Щелкните правой кнопкой по `pp09` → **ERD For Schema**. Расположите таблицы так, чтобы связи были видны. Это демонстрация реализованной схемы; проектная схема отдельно находится в `diagrams/PP09_DB_GOST.drawio`.
9. Откройте Query Tool и выполняйте запросы из `scripts/evidence.sql` по одному разделу. Для просмотра полного содержимого таблицы используется View/Edit Data → All Rows.

На скриншотах подключения закройте пароль и полные строки подключения. Хеши паролей и токены сеансов для демонстрации не нужны.

## 5. Резервная копия и контроль восстановления

В терминале с `.env`:

```powershell
npm run local:backup -- backups/pp09-check.json
```

Создайте в Neon **еще одну пустую базу `pp09_restore`**. Добавьте в `.env` ее прямую строку как `RESTORE_DATABASE_URL_DIRECT`. Не запускайте `local:init` для базы восстановления: она должна остаться пустой.

```powershell
npm run local:restore -- backups/pp09-check.json
```

В pgAdmin зарегистрируйте второе подключение к `pp09_restore`. Выполните запрос количества строк из раздела 2 `scripts/evidence.sql` на исходной и восстановленной базе. Количество должно совпасть во всех постоянных таблицах; `admin_sessions` в восстановленной базе пустая. Выполните соединения из разделов 3–5, чтобы показать сохранение связей.

Копия содержит хеши учетных записей и данные обращений. Храните ее локально; она исключена из Git. В непустую схему скрипт восстановление не выполняет.

## Если запуск не удался

| Сообщение или симптом | Проверка |
|---|---|
| `password authentication failed` | В строке подключения указаны актуальные роль и пароль Neon; URL скопирован целиком |
| `relation pp09.categories does not exist` | Выполнен `npm run local:init`; Render запускает `db:init` перед сервером |
| Тайм-аут подключения | Проект Neon активен; hostname и база выбраны правильно; строка содержит `sslmode=require` |
| `ADMIN_USER` / `ADMIN_PASSWORD` | Логин и пароль соответствуют ограничениям; значения заданы в `.env` либо Render |
| Закрытый раздел возвращает на вход | Откройте `/login` и войдите; на Render используйте HTTPS |
| После входа на localhost нет сеанса | Не задавайте локально `NODE_ENV=production`: cookie Secure предназначена для HTTPS |
| 429 при отправке или входе | Подождите 30 секунд для формы либо минуту после серии неверных паролей |
| Ошибка непустой БД при восстановлении | Назначение — отдельная пустая БД, без предварительного `db:init` |
